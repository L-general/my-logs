## 逐题复盘

### A — 字符串构造（签到题）

**题意**（推测）：给定整数 n，输出 n 个 "CU" 再接一个 "C"。

**思路**：直接从 1 到 n 循环输出 "CU"，最后输出 "C"。没有任何陷阱，纯签到。

**教训**：签到题不要想多，写完就跑，把时间留给后面的题。

### B — 整除与取模

**关键代码**：
```cpp
ll ans = (n / 2 + 1) % mod;
```

**思路**：答案公式 `⌊n/2⌋ + 1` 取模 998244353。推导过程需要把原问题转化为计数问题，最终化简到这个简洁形式。

**教训**：数学题推到最终公式再写代码，模运算记得在每一步都取模。

### D — 矩阵差异的奇偶性

**关键代码**：
```cpp
int ans = 0;
for (int i = 0; i < n; i++)
    for (int j = 0; j < m; j++)
        if (A[i][j] != B[i][j])
            ans++;
cout << ans % 2;
```

**思路**：统计两个 n×m 字符矩阵中有多少个位置不同，输出差异个数的奇偶性（0 或 1）。

**分析**：题目本质是在问"两个矩阵的汉明距离 mod 2"。奇偶性是很多组合游戏 / 图论问题的关键不变量，这题可能是一个更大结论的前置引理。

**教训**：看到 mod 2 就要意识到这很可能是某个不变量（invariant），不需要精确计数值，只需要奇偶性。

### E — 四个表达式比大小

**关键代码**：
```cpp
double x1 = log(a + b);      // ln(a+b)
double x2 = log(a) + log(b);  // ln(a×b)
double x3 = b * log(a);       // ln(a^b)
double x4 = a * log(b);       // ln(b^a)
```

**思路**：比较 a+b、a×b、a^b、b^a 四个值的大小。直接用原始值会溢出，所以取对数比较。题目给出一个编号 c（1≤c≤4），判断第 c 个表达式是否为最大值。

**潜在问题**：
- `log(a+b)` 在 a+b 很大时可能和其他值接近，浮点 `==` 比较在边界情况下可能出错
- `log(a) + log(b)` 比先乘再取 log 更安全（防止乘积溢出），但本题已取对数不存在此问题

**教训**：大数比较 → 取对数。浮点比较用 `fabs(a-b) < eps` 更稳健，但这题数据可能不强所以直接 `==` 也能过。

### F — 博弈论（打表题）

**文件名**：`F遇到博弈论老老实实打表去吧.cpp`

**关键代码**：
```cpp
if (n >= 8 && n != 9 && n != 11)
    cout << "kou\n";   // 先手胜
else
    cout << "yukari\n"; // 后手胜
```

**思路**：这是一道经典的取石子 / 减法游戏类博弈题。做法是对小规模 n 暴力求 SG 函数 / 必胜必败态，然后**打表找规律**。

打表结果：n ≥ 8 且 n ≠ 9, 11 时先手（kou）必胜，其余后手（yukari）必胜。

**复盘亮点**：
- 文件名本身就是一句忠告——遇到博弈论不要死磕推导，先打表看看有没有规律
- 大多数校赛级别的博弈题，SG 值都会有周期性或分段规律

**教训**：博弈题三件套 → ①小数据暴力求 SG ②打印表格 ③人眼找规律。找到规律后代码往往只有 5 行。

### J — 字符串升级（贪心）

**题意**（推测）：给定 n 个只含 'r', 'e', 'd' 的字符串，每个字符串的"价值"取决于包含的不同字符种类数：
- 0 种 → 0 分
- 1 种 → 1 分
- 2 种 → 2 分
- 3 种 → 4 分

你有 k 次操作，每次可以给某个字符串增加一种它还没有的字符。目标是最大化总分。

**初版代码的 Bug**（`J.cpp`）：
```cpp
int temp = n - 1;   // n 已经在 while(n--) 中被减到 0 了！
while (k >= 0 && temp >= 0)
{
    if (v[temp] == 3) { temp--; }       // bug: 已经是3还一直往前移
    else if (v[temp] == 2) { temp--; k--; v[temp] = 3; }  // bug: 给 v[temp-1] 赋值
    ...
}
```

两个致命 bug：
1. **n 已变为 0**：`while(n--)` 结束后 n = -1（循环退出条件），所以 `temp = n - 1` = -2，循环直接跳过
2. **赋值对象错误**：`temp--` 后再 `v[temp] = 3`，实际上是给前一个元素赋值，不是当前元素

**修复版**（`J_fixed.cpp`）：

改进点：
1. 用 `on` 保存原始 n 值
2. 引入结构体 `{shu, lon}` 同时记录不同字符数和字符串长度，因为短字符串不能容纳太多不同字符
3. 按 `shu` 升序、`lon` 升序排序后，从后往前贪心，优先升级当前价值最高且还能升级的字符串
4. 分情况仔细处理各种 lon 和 k 的组合

**贪心策略**：
```
已有3种 → 已满，跳过
已有2种 + len>2 → 花1次升级到3种
已有2种 + len=2 → 无法再增加（长度不够）
已有1种 + len>2 + k≥2 → 花2次直接升到3种
已有1种 + len=2 + k≥2 → 花1次升到2种
已有1种 + len=1 → 无法升级
已有1种 + k=1 → 花1次升到2种
```

**教训**：
- 循环后不要再使用被修改过的循环变量（n 在 `while(n--)` 后被破坏）
- 字符串升级类问题要考虑**长度约束**（最多有多少种不同字符 ≤ 字符串长度）
- 贪心要先想清楚**升级的性价比**：从 2→3 收益 +2 花 1 次，从 1→3 收益 +3 花 2 次，从 1→2 收益 +1 花 1 次。性价比排序：2→3（效率 2）> 1→2（效率 1）= 1→3（效率 1.5）—— 所以优先把 2 种的升到 3 种

### 需要改进的地方
- **变量生命周期**：J 题初版在循环后使用了已失效的变量，这是 C++ 新手常见问题，要养成"循环变量只用于循环"的习惯
