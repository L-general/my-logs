### 2.1 EEEEE — Dijkstra + 0-1 BFS（⭐⭐⭐⭐）

**题意**：n 个节点 m 条边的无向图，电动车电池续航 D。部分节点有充电桩。从起点 s 到终点 t，求最少充电次数（不含起点和终点），无法到达输出 -1。

**思路**：这道题的关键在于**状态压缩**——我们只关心"关键点"（起点、终点、所有充电桩）之间的距离，而不是所有节点。

```
阶段一：Dijkstra 多源最短路
  对每个关键点跑一次 Dijkstra，得到 K×K 的距离矩阵 dist_mat[u][v]。
  复杂度：O(K · (n+m) log n)，K = 充电桩数量 + 2。

阶段二：0-1 BFS 求最少充电次数
  在关键点构成的完全图上做 0-1 BFS：
    - 从关键点 u 到 v，如果 dist_mat[u][v] ≤ D，则边存在
    - 如果 v 是终点，边权 = 0（不需要充电）
    - 如果 v 是充电桩，边权 = 1（需要充电一次）
  deque 维护，0 权插队首，1 权插队尾。
```

**核心代码回顾**：
```cpp
// Dijkstra 部分：标准模板
priority_queue<pair<long long, int>, vector<...>, greater<...>> pq;
while (!pq.empty()) {
    long long dis = pq.top().first;
    int u = pq.top().second;
    pq.pop();
    if (dis > d[u]) continue;     // 惰性删除（过时状态跳过）
    for (auto &e : adj[u]) {
        if (d[u] + e.w < d[e.to]) {
            d[e.to] = d[u] + e.w;
            pq.push({d[e.to], e.to});
        }
    }
}

// 0-1 BFS 部分：边权决定插入位置
int cost = (keys[v_idx] == t ? 0 : 1);  // 到终点不花钱
if (min_charges[u_idx] + cost < min_charges[v_idx]) {
    min_charges[v_idx] = min_charges[u_idx] + cost;
    if (cost == 0) q.push_front(v_idx);
    else           q.push_back(v_idx);
}
```

**收获**：
- 掌握了"关键点压缩"的建模技巧：把 n 个节点的图压缩成 K 个关键点
- 复习了 Dijkstra 的惰性删除写法（`if (dis > d[u]) continue`）
- 复习了 0-1 BFS 的 deque 写法

### 2.2 FFFF — 对顶堆维护中位数（⭐⭐）

**题意**：动态插入数字，每次查询输出当前集合的中位数。

**思路**：对顶堆是维护动态中位数的经典技巧：

```
大根堆 L：存较小的一半（堆顶是较小一半中最大的）
小根堆 R：存较大的一半（堆顶是较大一半中最小的）

插入 x：
  若 x ≤ L.top() → 入 L
  否则          → 入 R

平衡：中位数位置 = (size+1)/2（靠左）
  L.size() > mid  → L 弹出到 R
  L.size() < mid  → R 弹出到 L

查询：L.top() 即为中位数
```

**复杂度**：每次插入 O(log n)，每次查询 O(1)。

**核心代码回顾**：
```cpp
priority_queue<int> L;                              // 大根堆（默认）
priority_queue<int, vector<int>, greater<int>> R;   // 小根堆

int mid = (L.size() + R.size() + 1) / 2;            // 中位数位置
while (L.size() > mid) { R.push(L.top()); L.pop(); }
while (L.size() < mid) { L.push(R.top()); R.pop(); }
```

**收获**：掌握了 `priority_queue` 的两种声明方式及平衡维护。

**延伸**：对顶堆也可以用来求第 k 大的数、滑动窗口中位数等。

### 2.3 GGG — 前缀和 + `__int128` + 二分查找（⭐⭐⭐）

**题意**：n 个元素的数组，每个元素乘 k 得到 `arr[i]`。每个元素有一个标记：若为 `S`，值不变；否则值乘 2。问是否存在一个区间 `(x, y]`（x < y），使得左右两半元素和相等。若存在，输出满足条件的最大区间值；否则输出 -1。

**思路**：

```
prearr[i] = 前 i 个元素的和（0-indexed前缀和）

对于每个可能的左端点 x（从大到小枚举）：
  y_val = total - prearr[x]    // 右半段需要的"半总和"
  若 y_val ≥ prearr[x]          // 保证左半 ≤ 右半
    在 prearr[] 中二分查找 y_val 的位置 y
    找到 → 答案是 y_val - prearr[x]（即中间区间的和）
```

**核心代码回顾**：
```cpp
__int128 arr[n];               // 用 __int128 防止溢出
__int128 prearr[n + 1];
prearr[0] = 0;
for (int i = 0; i < n; i++)
    prearr[i + 1] = prearr[i] + arr[i];

__int128 q = prearr[n];        // 总和
for (int x = n; x >= 0; x--) {
    __int128 y = q - prearr[x];
    if (y < prearr[x]) continue;
    if (binary_search(prearr, prearr + n + 1, y)) {
        m = y - prearr[x];
        break;                  // 从大到小找，第一个就是最大的
    }
}
```

**收获**：
- 学会了 `__int128` 的使用方法（g++ 支持，但不能直接 `cin/cout`）
- 前缀和 + `binary_search` 的组合模式
- 从大到小枚举保证了找到的是最优解

**注意**：`__int128` 不能被 `cin/cout` 直接读写，输入时需要用 `long long` 中转；输出时取模后转回 `long long`。

### 2.4 HHHH — 数学思维·读题题（⭐）

**题意**：有范围操作和范围查询，但所有查询的答案恒为 0。

**思路**：题目名字"数学孩子读题吧"已经暗示了——关键在于读懂题目条件。可以证明无论怎么操作，查询结果都是 0，所以直接输出 0 即可。

```cpp
// 查询操作直接输出 0
while (m--) {
    int op; cin >> op;
    if (op == 1) {
        int l, r, x; cin >> l >> r >> x;  // 读取但不处理
    } else {
        int l, r; cin >> l >> r;
        cout << 0 << endl;                 // 恒为 0
    }
}
```

**教训**：
- **先想清楚再写代码**：不要看到"区间操作"就无脑上线段树
- 数学推导往往能让复杂问题瞬间简化
- 题目名字有时就是提示

### 2.5 MMM — 小小贪心（⭐⭐）

**题意**：有 n 个物品，每个物品有体积 `arr[i]`。有若干"盒子"，第 j 个盒子的容量为 `c >> j`（c 的二进制第 j 位）。每个物品必须放入一个能容纳它的盒子，问最少需要额外买多少个盒子（每个物品装不下就多买一个盒子）。

**思路**：贪心——大物品优先，尽量塞进刚好够放的最小盒子。

```
1. arr 降序排列（大体积优先处理）
2. brr[j] = c >> j，即 c 的二进制表示（每个位对应一个可用盒子容量）
3. 对每个物品 arr[i]：
     从小到大找第一个能放下 arr[i] 的盒子 brr[j]
     找到 → 使用该盒子（标记 used）
     找不到 → cost++（买新盒子）
```

**核心代码回顾**：
```cpp
sort(arr, arr + n, greater<int>());    // 降序

for (int i = 0; i < n; i++) {
    int best = -1;
    for (int j = n-1; j >= 0; j--) {   // 从最小的盒子开始找
        if (!used[j] && brr[j] >= arr[i]) {
            best = j;
            break;                       // 取最小的够用的
        }
    }
    if (best != -1) used[best] = true;
    else cost++;                         // 需要额外买
}
```

**收获**：
- 贪心策略：大物件优先 + 选最小够用盒子（类似"最佳适应"装箱算法）
- 位运算表示盒子容量：`c >> i` 把 c 的二进制位展开成不同大小的盒子
- `sort(arr, arr + n, greater<int>())` 降序排列的写法

### 2.6 cccc — 按位前缀和 + 区间 AND（⭐⭐）

**题意**：n 个数的数组，q 次查询，每次求 `[l, r]` 区间内所有元素的**按位与**（bitwise AND）。

**思路**：AND 运算的性质——某一位为 1 当且仅当区间内**所有**数的该位都是 1。

```
预处理：对每一位 j（0~30），维护前缀和 arr[j][i]
  arr[j][i] = 前 i 个数中第 j 位为 1 的个数

查询 [l, r]：
  对于每一位 j：
    若 arr[j][r] - arr[j][l-1] == lenth（区间长度）
    → 该位全为 1，ans |= (1 << j)
```

**核心代码回顾**：
```cpp
int k = 31;                              // 31 位（0~30）
int arr[31][n + 1];                      // 每位一个前缀和数组

// 预处理
for (int i = 1; i <= n; i++) {
    int x; cin >> x;
    for (int j = 0; j < k; j++)
        arr[j][i] = arr[j][i-1] + ((x >> j) & 1);
}

// 查询
int lenth = r - l + 1;
for (int i = 0; i < k; i++) {
    if (arr[i][r] - arr[i][l-1] == lenth)  // 整个区间该位全为 1
        ans |= (1 << i);
}
```

**复杂度**：预处理 O(31n)，每次查询 O(31)，非常适合 n 和 q 都较大的场景。

**收获**：
- AND 运算的单调性：位为 1 的条件比 OR/XOR 更严格（要求全 1）
- 按位拆分的技巧，将区间 AND 转化为每位的前缀和判定
- `((x >> j) & 1)` 提取第 j 位的标准写法

## 四、主要收获

### 4.1 新学到的技巧

1. **0-1 BFS**（E题）：边权只有 0 和 1 时，用 deque 替代 Dijkstra 的优先队列，复杂度从 O(E log V) 降到 O(V + E)
2. **对顶堆**（F题）：动态维护中位数的标准做法，比每次排序 O(n log n) 快得多
3. **`__int128`**（G题）：g++ 的 128 位整数扩展，适合中间结果可能爆 `long long` 但最终结果不爆的场景
4. **按位前缀和**（C题）：将不可逆运算（AND）转化为每位独立的前缀和判定

### 4.2 思维方式提升

- **先建模再编码**（E题）：不直接在 n 个节点上跑 BFS，而是压缩到 K 个关键点
- **先推导再动手**（H题）：不是所有"区间操作"都需要数据结构
- **贪心策略选择**（M题）：大物件优先 + 最小够用 = 最佳适应

### 4.3 还存在的不足

1. **Dijkstra 变体不熟练**：E 题写了较久，0-1 BFS 的 deque 用法需要多练
2. **`__int128` 不常用**：G 题的输入输出绕了一下（不能直接 cin/cout）
3. **贪心正确性证明薄弱**：M 题凭直觉写，缺乏严谨证明
